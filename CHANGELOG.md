## [Unreleased]

### Added
- Project foundation: Cargo workspace (`nfd-core`, `nfd-rules`, `nfd-platform`, `nfd-cli`), CI, release pipeline skeleton.
- DevCache catalog v0 (`docs/DEVTOOL_CACHE_CATALOG.md`) and the `ai-tools` / `windows-system` rule packs.
- Rule-pack loader and validator (`nfd rules validate`).
- Development plan (`docs/PLAN.md`) including the §13 feature-expansion map (v1.0 / v1.x / v2 tags and the "never do" list), mirrored in the README roadmap.
- Scanner, standard mode (`nfd_core::scanner`): parallel directory walk that reads metadata straight from NTFS directory listings (~1M entries in under 4 s on an SSD), never follows junctions, symlinks or mount points, counts hard-linked data once, and collects unreadable paths as issues instead of failing. Progress streams over a `ScanEvent` channel and scans can be cancelled.
- Directory size roll-up, largest files and per-extension breakdown.
- `nfd scan <path>` with `--top`, `--json` (schema `nanofreedisk.scan.v1`, see `docs/schema/scan-v1.schema.json`), `--csv`, `--min-size`, `--threads`, `--exact-links` and a progress spinner. `--fast` is accepted but falls back to the standard scan until the NTFS MFT reader lands (cargo feature `mft`).
- `nfd_platform::fsinfo`: Windows file metadata (allocation size, compression-aware size, reparse tag, file ID, link count) via `windows-sys`.
- Desktop app (`apps/nanofreedisk`, Tauri 2 + Svelte 5): drive overview, background scan with live progress and cancel, treemap and sunburst, virtualized folder tree, largest files, file types, search & filters (name/glob, size, extension, date, hidden/system, cloud-only), details panel, Show in Explorer / Open / Copy path, JSON/CSV export.
- Move to Recycle Bin from Analyze, behind `nfd_core::safety::check_manual_delete`: volume roots, the Windows folder, Program Files, credentials and system folders on every drive are refused; user/AppData/Temp folders themselves are refused while items inside them can be picked; links, junctions and folders containing mount points are refused; every item is re-checked on disk right before the move, large deletions need an extra confirmation, and Windows asks before anything too big for the bin would be deleted permanently (`nfd_platform::trash`).
- `nfd_core::query` (search & filters over a scan) and `ScanTree::remove` (keep totals right after deletions); `nfd_platform::volumes` and `nfd_platform::appearance` (Windows accent color).
- English and Vietnamese UI via Fluent (`locales/`), with `scripts/check-locales.mjs` keeping both complete; Light / Dark / System / Custom themes with presets, `theme.toml` import/export and WCAG contrast warnings; adjustable text size.
- App icon and brand guide (`docs/BRAND.md`); GUI toolkit decision record (`docs/adr/0001-gui-toolkit.md`).
- **Old & large** view (`nfd_core::insights::old_and_large`): files above a size you choose, big files not modified for a year or more, and old installers / disk images left in any `Downloads` folder; pick several and move them to the Recycle Bin through the same safety checks as Analyze.
- **Tidy up** view (read-only): outermost empty folder trees (`insights::empty_folders`; unreadable folders are never called empty, and folders the safety rules protect are skipped while empty folders inside them are listed) and shortcuts whose target is gone (`nfd_core::shortcut`, a Shell Link reader that never resolves through the shell or touches network drives; "target missing" vs "drive not connected").
- Self-contained **HTML report** (static SVG treemap, largest items and files, file types, Old & Large summary, current theme colors, EN/VI) from Analyze → Export.
- **Simple / Expert** mode: Simple hides advanced filters, attributes, unreadable paths and JSON/CSV export; Expert shows everything plus the equivalent `nfd` command with a copy button.
- **Command palette (Ctrl+K)**: views, actions, drives, folders of the current scan, language / theme / text size; matching ignores case and Vietnamese diacritics.
- `scripts/check-locales.mjs` also fails when the UI uses a message key missing from `locales/en/app.ftl`; `scripts/gui-smoke.mjs` covers the new commands and views.
- **Scan history** (`nfd-history`, SQLite compiled in): every scan can be saved as a compact snapshot (folder sizes from 1 MB, large files) on this PC only; 30 snapshots per folder, 300 in all; a damaged database is set aside and replaced. Turn it off or clear it in Settings.
- **What changed?** tab in Analyze: compares the scan with an earlier one of the same folder — folders that grew or shrank (shown at the most specific level), large files added or removed, and the change in the drive's free space; click a row to jump to it.
- **Health score** on Home (`nfd_core::health`): 0–100 from free space per drive, how fast each drive fills (from the scan history) and the Old & Large total, with the three biggest reasons and a button to fix each.
- `nfd diff <root> [--since 7d] [--json]` compares saved scans from the command line (`nfd scan --save` saves one; the app's history is shared), and the HTML report gains a "What changed since…" section.
- **Folder Encyclopedia**: 23 English/Vietnamese articles in `rules/encyclopedia/*.md` (WinSxS, Windows Installer, pagefile, `$Recycle.Bin`, AppData\Local\Packages, .ollama, node_modules, Unity Library, Rust target, .git…) explaining what a folder is, what happens if it is deleted and what to do instead. Shown as "What is this?" in the Details panel and by `nfd explain <path>`; validated by `nfd rules validate`. Information only — no delete action is attached.
- **Age heatmap** tab in Analyze (space by last-modified age per sub-folder), the **owner** of the selected item (Expert mode), and **orphan junctions / broken symbolic links** in Tidy up (read-only).
- "If you do this…" tooltips on every control that changes something.
- **Explorer integration**: optional "Analyze with NANOFreeDisk" in the right-click menu of folders and drives (per user, no admin rights; removed when turned off or on uninstall), `nanofreedisk.exe <folder>` starts a scan, and a second launch hands its folder to the window already open.
- Demo recording of the real app (`scripts/demo-video.mjs`, `docs/assets/demo/`).
- **SafetyGate** (`nfd_core::safety::gate`, Phase 3): one check for every deletion, by origin (picked by hand vs. a rule's risk level). Lexically it refuses volume roots, `%SystemRoot%` (rules may only reach `Temp`, `Logs\CBS`, `Logs\DISM`, `Minidump`, `LiveKernelReports`, `SoftwareDistribution\Download` and `MEMORY.DMP`), Program Files, credentials, user data for rules, containers such as `%TEMP%` itself, alternate data streams, device paths and reserved names (`NUL`, `COM1`…) and drive-relative paths. Right before acting it re-checks the disk: the final path (links among the parents, 8.3 short names, `\\?\`), links, a volume other than the one the path names, SYSTEM files in Windows/program folders, program images below `%SystemRoot%` (stricter than an Authenticode check), cloud placeholders, and anything that changed since it was planned. 304 table-driven cases plus property tests.
- **Restart Manager** lock detection (`nfd_platform::locks`): the processes holding a file open are named instead of failing; the app never closes them.
- **Rule matcher** (`nfd_rules::matcher`): per-component globs (`*`, `?`, `{a,b}`, `**`), `min_age_days`, `exclude`, `requires_closed`; never follows links; a folder with something that must stay inside (a link, an excluded or too-new file) is split instead of offered whole. New packs `browsers` (Chrome, Edge, Brave, Vivaldi, Opera, Firefox: HTTP/code/GPU/Service Worker caches only — never cookies, history, passwords, bookmarks or profiles) and `gpu-shader-cache` (moved out of `windows-system`); every shipped rule has a Vietnamese `impact_vi`; the packs are compiled into the binaries.
- **Planner / Executor / Quarantine / Undo journal**: hand-picked items go to the Recycle Bin, rule matches to the quarantine — a rename into the app's data folder on the system drive or a hidden, user-only `<drive>\.nfd-quarantine` elsewhere (Recycle Bin on FAT/exFAT/network drives), kept 7 days. Folders with files in use are moved file by file. Every operation is journaled in the history database (schema 2) and a 90-day audit log, and can be restored with the original bytes and dates — Recycle Bin items too (`$I`/`$R` records).
- `nfd clean [--pack] [--rule] [--level safe|caution|advanced] [--dry-run] [--apply] [--permanent] [--json]`, `nfd quarantine list|show|restore|purge` and `nfd plan explain <path>`; CI asserts that a whole-system dry run proposes nothing protected.
- **Clean** view (grouped by pack and rule: size, files, "if deleted…", apps to close, file preview, one-click "Clean safely", confirmation with the total, progress and cancel; permanent delete only in Expert mode for Safe items after typing DELETE) and **Activity** log (operations by day, details, Restore per operation or item). Home's "Free X GB safely now" uses the rule scan; the Health Score counts safe junk. Analyze and Old & Large deletes now go through the same Planner → SafetyGate → Executor path and appear in Activity; Tidy up can move empty folders and broken shortcuts to the quarantine.
- **Hardware view** (docs/HARDWARE_MONITOR.md, read-only, no driver, no admin):
  - **Overview** (`nfd-hwinfo`, schema `nanofreedisk.hwinfo.v1`): system and Windows build, CPU from CPUID with the hybrid P/E split, caches and clocks, mainboard / BIOS / memory sticks from SMBIOS, GPUs, disks (bus, SSD/HDD, temperature), monitors, network adapters, battery wear and cycles; copy as text in the UI language, JSON export (Expert). Serial numbers, UUIDs, MAC and IP addresses are never collected.
  - **Sensors** (`nfd-sensors`): Value / Min / Max tree like LibreHardwareMonitor with a one-minute sparkline — CPU load per thread and estimated clock, memory, GPU load per engine / VRAM / temperature / clocks / power (D3DKMT, PDH, NVML), disk temperature and activity, battery, network, ACPI zones. A sleeping discrete GPU is never woken up. Sampling runs only while the tab or the Home card is shown. CPU temperatures, power and voltages say they need Advanced sensors (PawnIO, opt-in, coming with the elevated helper).
  - **Home temperature card**: CPU / GPU / hottest disk, opens Sensors.
  - **Tasks** (`nfd-tasks`): Task Manager-like list with CPU, private memory, disk I/O and GPU per process, publisher (Authenticode), Apps / Background / Windows groups, tree view, search and sort. Close app / End process / End process tree only when the user picks it and confirms; the process is re-identified by PID and creation time, critical / protected / core Windows processes and NANOFreeDisk itself are hard-blocked, svchost (with its services), Explorer and programs in the Windows folder need a second confirmation; every attempt is logged to `logs/tasks.log`.
  - CLI: `nfd hw [--json]`, `nfd sensors [--watch] [--simple] [--json]`, `nfd ps [--sort cpu|memory|io|gpu|name|pid] [--json]` (read-only).
- **Advanced sensors (PawnIO, opt-in, ADR 0002)**: an elevated helper (`nanofreedisk.exe --elevated-helper`, `nfd-helper`) started through UAC on request, talking to the app over a local named pipe with a three-request protocol (discover / sample / shutdown) and PID + executable checks on both ends. Through PawnIO's official IntelMSR module (SHA-256 pinned, IOCTL interface only, `ioctl_read_msr` only) it adds CPU package and per-core temperatures, core max / average, TjMax, RAPL package / cores / graphics / platform power, PL1 / PL2, per-core VID, per-core and effective clocks. The Sensors tab shows PawnIO's state (not installed / not running / module missing) and a button to turn them on; `nfd sensors --advanced` does the same from an elevated prompt. Nothing is ever written to the hardware.
- **AMD Zen Advanced sensors** (PawnIO AMDFamily17, SHA-256 pinned, read functions only): Tctl / Tdie, per-CCD temperatures, package and per-core power, per-core VID, effective clocks. Not yet verified on AMD hardware. Mainboard Super I/O (fans, board voltages) is deliberately not probed until a table of chips verified on real boards exists: entering a chip's configuration mode writes to ports 0x2E / 0x4E, which on laptops often belong to the embedded controller.
- **Temperature alerts** (Hardware → Sensors, off by default): a Windows notification and an in-app toast when the CPU reaches 95 °C, a GPU 90 °C or a drive its own warning temperature (NVMe WCTEMP; 70 °C when it reports none), once per episode with a 15-minute cooldown. While on, sensors are read every 5 s in the background; otherwise only while a view asks.
- **Last 24 hours** chart of the hottest CPU / GPU / drive per minute, kept in `thermal-24h.json`, and a **Health Score** contribution for parts that ran hot (−8) or warm (−2) in that window, with a "See temperatures" fix button.
- Drives' own warning / critical temperatures shown in the Sensors tree and used for colors, alerts and the Health Score.
- Validation against LibreHardwareMonitor on the reference i9-13900HX (`docs/hwmon-validation.md`, `scripts/hw-compare-lhm.mjs`); the bus clock is now TSC-derived and core registers are read in two passes, as LHM does.
- The i18n loader and `scripts/check-locales.mjs` read every `locales/<lang>/*.ftl` (one file per feature area).
- **DevCache catalog** (Phase 4, `docs/PHASE4_DEVCACHE.md`): new rule packs `ide-editors` (VS Code and its forks, JetBrains, Visual Studio, Android Studio / SDK, Sublime Text, Zed, Neovim, Notepad++, Obsidian, Postman, Docker Desktop), `package-managers` (npm, pnpm, Yarn, Bun, Deno, node-gyp, TypeScript, Electron, Playwright, Puppeteer, pip, uv, Poetry, Conda, Cargo, rustup, Go, NuGet, .NET, vcpkg, Gradle, Maven, Composer, Dart / Flutter, Scoop, Chocolatey, winget) and `game-engines` (Unity, Unity Hub, Unreal, Epic Games Launcher, Godot), and more `ai-tools` rules (Continue, Cline, Roo Code, Copilot CLI, PyTorch, Keras, Jan, GPT4All, Ollama logs): 123 DevCache rules, each with English and Vietnamese "if deleted…" text. Packs marked `devcache = true` form the DevCache view.
- The paths of every 🔴 Protected rule are now excluded from **every** rule, so a broad cache rule can never sweep up config, credentials or memories another rule keeps.
- **DevCache view** (`nfd-devtools`): caches grouped vendor → app → folder with size, files, last change, risk level, "if deleted…", apps to close and whether they are running, a preview with Show in Explorer, "Clean safely" per vendor and for all vendors, and the 🔒 list of what is kept on purpose; per-vendor reminder thresholds with an optional notification (Settings → Dev caches).
- **Toolchains** tab and `nfd toolchains`: rustup toolchains, Node versions (nvm-windows, fnm, Volta), Pythons (pyenv-win, python.org, uv), Conda environments, IDE JDKs, Go SDKs, Android SDK packages, .NET SDKs, Unity and Unreal editors, Flutter (fvm), Visual Studio instances and WSL / Docker disks with size, last change and the proper uninstall command or app — never a raw folder delete.
- **Repositories** tab and `nfd repos <root>` / `nfd repos clean <root>`: finds git repositories and projects without following links, shows `.git` size, last commit, uncommitted changes, recent / stale, and the build output found by marker files (`Cargo.toml` → `target`, `package.json` → `node_modules`, Unity `Library`, Unreal `Intermediate` / `DerivedDataCache`, Godot `.godot`, …). Generic names (`build`, `dist`, `bin`, `obj`) are offered only when git ignores them, folders with tracked files never, and projects active in the last 7 days keep theirs unselected; cleaning moves them to the quarantine.
- **Package stores** tab and `nfd stores` / `nfd stores run <id>`: each package manager's own cleanup command (`npm cache clean --force`, `pnpm store prune`, `pip cache purge`, `uv cache clean`, `conda clean --all`, `go clean -cache` / `-modcache`, `dotnet nuget locals all --clear`, …) runs only after its exact command line is shown and confirmed — without a shell, with a timeout, cancellable — and is recorded in Activity; commands whose data cannot be downloaded again (`ollama rm`, `hf cache delete`, `docker system prune`, `git gc`) are guide-only.
- **Unknown folders** tab and `nfd devcache unknown`: cache-like folders no rule knows yet, always "unverified" and never cleaned, with a pre-filled rule-proposal issue link that writes the folder as a variable (no user name).
- `nfd devcache [list|clean|unknown]` (`--vendor`, `--level`, `--json` schema `nanofreedisk.devcache.v1`).
- The rule matcher walks rules in parallel: a whole-machine dry run with all 150 rules takes ~7 s instead of ~31 s on the reference PC.
- **Duplicates, core** (`nfd-dupes`, Phase 5): files with identical contents across one or more folders or drives — size first, then BLAKE3 of three 16 KiB samples, then of the whole file (1 MiB sequential reads in low-priority background threads; several files at once on SSDs, one at a time on spinning disks), optionally byte by byte. Empty and small files, cloud placeholders (never opened, so nothing is downloaded), reparse points, SYSTEM files, protected locations and application folders (`node_modules`, `.git`, Steam libraries, `%LOCALAPPDATA%\Programs`…) are left out; hard-linked names of one file count as one copy; a file that changes while it is read never joins a group. Copies in cloud-sync folders, git working trees and read-only files are flagged. Hashes are cached in the history database by volume, file id, size and last write, so a second run reads almost nothing.
- `nfd dupes <path...>` with `--min-size`, `--ext`, `--include-app-dirs`, `--paranoid`, `--threads`, `--json` (schema `nanofreedisk.dupes.v1`, `docs/schema/dupes-v1.schema.json`), `--csv` and `--no-cache`; `cargo bench -p nfd-dupes` and `docs/dupes-benchmark.md` (17.7 GiB of real files hashed at 1.2 GiB/s on the reference laptop: ≈ 78 s for 100 GB in the worst case).
- **Duplicates, keep and remove** (`nfd_dupes::keep`, `nfd_dupes::plan`): the copy that stays is chosen automatically (outside Downloads / Temp / Desktop, then the oldest; or oldest, newest, shortest path, inside preferred folders); copies in cloud-sync folders, git working trees, application folders and read-only files are kept first and never pre-selected. The planner refuses any selection that would leave a group empty (property-tested), and right before each copy is moved the keeper and the copy are hashed again in full — a keeper that changed or vanished skips its whole group. Copies go to the Recycle Bin or the quarantine through the SafetyGate, the executor and the undo journal (`nfd dupes --keep … --action recycle|quarantine --apply`).
- **Duplicates view** (sidebar, Ctrl+K): search the drive or folder open in Analyze, or folders and drives picked in the view (scanned on their own, Analyze and the scan history untouched), from a minimum size and for a file type; progress by step with Cancel; groups by wasted space with "Keep" and "Remove" per copy, a keep strategy for all groups, cloud-sync / git / app / read-only badges, image previews read by the app itself (never a cloud placeholder), Show in Explorer; Move to Recycle Bin (Expert: quarantine) after a confirmation that lists risky copies and needs an extra tick for them; Expert: CSV / JSON export and the equivalent `nfd dupes` command. "Find duplicates here" in Analyze's right-click menu and in Explorer's (per user, removed with the other entry and on uninstall); the Health card mentions the duplicates found; removals appear in Activity and can be restored.
- **Replace duplicates with links** (`nfd_platform::link`, executor modes `hardlink` / `clone`): a selected copy on the same drive as the copy kept becomes a block clone of it on ReFS / Dev Drive (copy-on-write, still independent files) or a hard link on NTFS. The link is made under a temporary name, the original moves to the quarantine, then the link takes its name — a failure at any step undoes the earlier ones. Restore in Activity puts the original back (same bytes and dates) and removes the link, leaving two independent files. Never offered across drives, on drives without links, in cloud-sync, git or application folders; hard links are pre-selected only for photos, videos, music, installers, disk images, archives and AI models, and the confirmation explains that hard-linked paths share one content. `nfd dupes --action hardlink [--link-other-types] --apply`.

### Changed
- **AI conversation history is never deleted** (PLAN §5.1): the SafetyGate protects the session / conversation folders of Claude Code and Claude Desktop, Codex, Gemini CLI, Antigravity, Copilot (VS Code and CLI), Cursor, Windsurf, Devin, ZCode, Trae, Kiro, opencode, Continue, Cline, Roo Code, Qwen Code, LM Studio and Jan, plus Aider chat logs and `.specstory` folders inside projects, against every origin — rules of any level, DevCache, Duplicates and items picked by hand — and refuses the folders that contain them. The rules that used to offer old transcripts (🟡 Claude Code / Codex sessions, Gemini CLI `tmp` and history, Copilot chat, Cursor and VS Code `workspaceStorage`, Windsurf Cascade, Continue, Cline, Roo Code) are now 🔴 Keep rules, and new Keep rules list the other agents' history in DevCache.
