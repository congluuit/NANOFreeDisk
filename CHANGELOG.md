# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres to [Semantic Versioning](https://semver.org/).

Entries are generated from Conventional Commits with `git-cliff`; edit by hand only to add context.

## [Unreleased]

### Added
- **Set up Advanced sensors in one click** (Hardware → Sensors): CPU temperatures need PawnIO and its official CPU module, which used to mean a manual download into a hidden folder. The app now downloads PawnIO's official installer and module from its author's GitHub releases, accepts them only when their SHA-256 matches the pinned values, installs PawnIO through Windows' administrator prompt and stores the module — then turns the sensors on.
- **Turn on automatically when the app opens**: after Advanced sensors were turned on once, the next start turns them on again (one Windows prompt per start; untick to stop).
- **macOS (preview)**: one universal app for Intel and Apple silicon Macs, macOS 11+ (`.dmg` and zipped `.app`, ad-hoc signed, not notarized yet). Analyze, Duplicates, Old & Large, Tidy up, DevCache and Activity work; deleting moves items to the Trash (Put Back and Activity → Restore work) or the quarantine. Protected on macOS: the system folders, iCloud Drive, Mail, Messages, keychains, app sandboxes, iPhone backups, Time Machine, Photos / Music / TV libraries, the inside of app bundles and document packages, and AI agents' chat history (ChatGPT, Codex, Copilot for Xcode, Ollama, Zed, Raycast besides the cross-platform tools). Duplicates counts APFS clones once and never pre-selects them, and never reads iCloud files that are not downloaded. A hint explains how to grant Full Disk Access. Clean, Drive health, Hardware and Monitor stay Windows-only for now. See the README's macOS section and `docs/MACOS.md`.

### Fixed
- Wrong CPU numbers right after opening a sensor view: load, power, effective clocks, network and GPU rates were computed over a few milliseconds on the first sample (e.g. 58 % CPU load at 20 %, inflated power maxima). Rate sources now wait 500 ms after discovery.
- The Home card no longer shows an ACPI thermal zone (often a fixed firmware value) as the CPU temperature; it says why the CPU value is missing and links to the setup instead.
- The estimated CPU clock is named "Average clock while busy" and is hidden once Advanced sensors report measured clocks.

## [0.1.1] - 2026-10-17

### Added
- **"Delete anyway…"** — the app's verdicts can be wrong (it kept Claude Code worktrees whose commits were already pushed, only because their sessions had been active that day), so what it keeps *by judgment* can now be overruled: Analyze → the details card, or a kept group in Suggestions → **Delete anyway…**, with the reason the app kept it and an explicit "I understand" tick. Nothing is deleted for good: a git worktree with nothing uncommitted is removed with `git worktree remove` (branch and commits stay), anything else moves to the quarantine (Cleanup history, kind *Deleted anyway*, restorable for 7 days). **Hard protections are not judgments and stay blocked** — Windows, Program Files, drive roots, credentials and AI conversation history (PLAN §5.1), and folders that hold them — and the app now says which one it is.
- Badges tell the two apart: **Better keep** (blue, the app's suggestion) vs **🔒 Protected** (red, never deleted). `nfd advise` marks them too.

### Fixed
- Installers: a failed install no longer leaves a broken entry behind. In the per-user NSIS package, a folder that needs administrator rights (Program Files) disables Next and says why; file errors no longer offer "Ignore"; a failed fresh install is rolled back (files, Apps & features entry, saved location); entries whose uninstaller is gone are cleaned up when either installer starts, so the next install can use another folder without a trip to Control Panel. The branded setup reports "cannot write to this folder" and rolls back the same way.
- Release notes list the branded `NANOFreeDisk-Setup-<version>-x64.exe` first, in bold, as the recommended download.
- Ending a process tree: a parent that exits on its own while it is being ended now counts as ended instead of failing with "access denied".
- Suggestions: a safe group that appears when the same scan is judged again (after git checked the agent worktrees) is ticked like the others.

### Changed
- CI and the release check build and test on Windows only; releases publish only the Windows packages (each includes `nfd.exe`).

Lexically it refuses volume roots, `%SystemRoot%` (rules may only reach `Temp`, `Logs\CBS`, `Logs\DISM`, `Minidump`, `LiveKernelReports`, `SoftwareDistribution\Download` and `MEMORY.DMP`), Program Files, credentials, user data for rules, containers such as `%TEMP%` itself, alternate data streams, device paths and reserved names (`NUL`, `COM1`…) and drive-relative paths. Right before acting it re-checks the disk: the final path (links among the parents, 8.3 short names, `\\?\`), links, a volume other than the one the path names, SYSTEM files in Windows/program folders, program images below `%SystemRoot%` (stricter than an Authenticode check), cloud placeholders, and anything that changed since it was planned. 304 table-driven cases plus property tests.

Folders with files in use are moved file by file. Every operation is journaled in the history database (schema 2) and a 90-day audit log, and can be restored with the original bytes and dates — Recycle Bin items too (`$I`/`$R` records).

- **Hardware view** (docs/HARDWARE_MONITOR.md, read-only, no driver, no admin):
  - **Overview** (`nfd-hwinfo`, schema `nanofreedisk.hwinfo.v1`): system and Windows build, CPU from CPUID with the hybrid P/E split, caches and clocks, mainboard / BIOS / memory sticks from SMBIOS, GPUs, disks (bus, SSD/HDD, temperature), monitors, network adapters, battery wear and cycles; copy as text in the UI language, JSON export (Expert). Serial numbers, UUIDs, MAC and IP addresses are never collected.
  - **Sensors** (`nfd-sensors`): Value / Min / Max tree like LibreHardwareMonitor with a one-minute sparkline — CPU load per thread and estimated clock, memory, GPU load per engine / VRAM / temperature / clocks / power (D3DKMT, PDH, NVML), disk temperature and activity, battery, network, ACPI zones. A sleeping discrete GPU is never woken up. Sampling runs only while the tab or the Home card is shown. CPU temperatures, power and voltages say they need Advanced sensors (PawnIO, opt-in, coming with the elevated helper).
  - **Home temperature card**: CPU / GPU / hottest disk, opens Sensors.
  - **Tasks** (`nfd-tasks`): Task Manager-like list with CPU, private memory, disk I/O and GPU per process, publisher (Authenticode), Apps / Background / Windows groups, tree view, search and sort. Close app / End process / End process tree only when the user picks it and confirms; the process is re-identified by PID and creation time, critical / protected / core Windows processes and NANOFreeDisk itself are hard-blocked, svchost (with its services), Explorer and programs in the Windows folder need a second confirmation; every attempt is logged to `logs/tasks.log`.
  - CLI: `nfd hw [--json]`, `nfd sensors [--watch] [--simple] [--json]`, `nfd ps [--sort cpu|memory|io|gpu|name|pid] [--json]` (read-only).
- **Advanced sensors (PawnIO, opt-in, ADR 0002)**: an elevated helper (`nanofreedisk.exe --elevated-helper`, `nfd-helper`) started through UAC on request, talking to the app over a local named pipe with a three-request protocol (discover / sample / shutdown) and PID + executable checks on both ends. Through PawnIO's official IntelMSR module (SHA-256 pinned, IOCTL interface only, `ioctl_read_msr` only) it adds CPU package and per-core temperatures, core max / average, TjMax, RAPL package / cores / graphics / platform power, PL1 / PL2, per-core VID, per-core and effective clocks. The Sensors tab shows PawnIO's state (not installed / not running / module missing) and a button to turn them on; `nfd sensors --advanced` does the same from an elevated prompt. Nothing is ever written to the hardware.

Not yet verified on AMD hardware. While on, sensors are read every 5 s in the background; otherwise only while a view asks.

Generic names (`build`, `dist`, `bin`, `obj`) are offered only when git ignores them, folders with tracked files never, and projects active in the last 7 days keep theirs unselected; cleaning moves them to the quarantine.

- **Unknown folders** tab and `nfd devcache unknown`: cache-like folders no rule knows yet, always "unverified" and never cleaned, with a pre-filled rule-proposal issue link that writes the folder as a variable (no user name).
- `nfd devcache [list|clean|unknown]` (`--vendor`, `--level`, `--json` schema `nanofreedisk.devcache.v1`).
- The rule matcher walks rules in parallel: a whole-machine dry run with all 150 rules takes ~7 s instead of ~31 s on the reference PC.
- **Duplicates, core** (`nfd-dupes`, Phase 5): files with identical contents across one or more folders or drives — size first, then BLAKE3 of three 16 KiB samples, then of the whole file (1 MiB sequential reads in low-priority background threads; several files at once on SSDs, one at a time on spinning disks), optionally byte by byte. Empty and small files, cloud placeholders (never opened, so nothing is downloaded), reparse points, SYSTEM files, protected locations and application folders (`node_modules`, `.git`, Steam libraries, `%LOCALAPPDATA%\Programs`…) are left out; hard-linked names of one file count as one copy; a file that changes while it is read never joins a group. Copies in cloud-sync folders, git working trees and read-only files are flagged. Hashes are cached in the history database by volume, file id, size and last write, so a second run reads almost nothing.
- `nfd dupes <path...>` with `--min-size`, `--ext`, `--include-app-dirs`, `--paranoid`, `--threads`, `--json` (schema `nanofreedisk.dupes.v1`, `docs/schema/dupes-v1.schema.json`), `--csv` and `--no-cache`; `cargo bench -p nfd-dupes` and `docs/dupes-benchmark.md` (17.7 GiB of real files hashed at 1.2 GiB/s on the reference laptop: ≈ 78 s for 100 GB in the worst case).
- **Duplicates, keep and remove** (`nfd_dupes::keep`, `nfd_dupes::plan`): the copy that stays is chosen automatically (outside Downloads / Temp / Desktop, then the oldest; or oldest, newest, shortest path, inside preferred folders); copies in cloud-sync folders, git working trees, application folders and read-only files are kept first and never pre-selected. The planner refuses any selection that would leave a group empty (property-tested), and right before each copy is moved the keeper and the copy are hashed again in full — a keeper that changed or vanished skips its whole group. Copies go to the Recycle Bin or the quarantine through the SafetyGate, the executor and the undo journal (`nfd dupes --keep … --action recycle|quarantine --apply`).
- **Duplicates view** (sidebar, Ctrl+K): search the drive or folder open in Analyze, or folders and drives picked in the view (scanned on their own, Analyze and the scan history untouched), from a minimum size and for a file type; progress by step with Cancel; groups by wasted space with "Keep" and "Remove" per copy, a keep strategy for all groups, cloud-sync / git / app / read-only badges, image previews read by the app itself (never a cloud placeholder), Show in Explorer; Move to Recycle Bin (Expert: quarantine) after a confirmation that lists risky copies and needs an extra tick for them; Expert: CSV / JSON export and the equivalent `nfd dupes` command. "Find duplicates here" in Analyze's right-click menu and in Explorer's (per user, removed with the other entry and on uninstall); the Health card mentions the duplicates found; removals appear in Activity and can be restored.
- **Replace duplicates with links** (`nfd_platform::link`, executor modes `hardlink` / `clone`): a selected copy on the same drive as the copy kept becomes a block clone of it on ReFS / Dev Drive (copy-on-write, still independent files) or a hard link on NTFS. The link is made under a temporary name, the original moves to the quarantine, then the link takes its name — a failure at any step undoes the earlier ones. Restore in Activity puts the original back (same bytes and dates) and removes the link, leaving two independent files. Never offered across drives, on drives without links, in cloud-sync, git or application folders; hard links are pre-selected only for photos, videos, music, installers, disk images, archives and AI models, and the confirmation explains that hard-linked paths share one content. `nfd dupes --action hardlink [--link-other-types] --apply`.
- **Duplicate folders** (`nfd_dupes::folders`, Folders tab, `nfd dupes --folders`): folders whose names and file contents are identical, reported at the top-most level only; a folder with anything left out of the search (or a file whose contents are unique) never matches, and a protected folder (such as Documents itself) is kept and never removed. Whole folders go to the Recycle Bin or the quarantine; each folder and the one kept are read again right before the move. JSON gains `folderGroups`.
- **Disk activity monitor, core** (`nfd-monitor`, Phase 6): per-process read / write rates and IOPS from each process's I/O counters (no admin rights needed; a PID reused by another process is never mixed up, a process that starts between two samples is counted from zero), physical disk throughput, queue length, latency and idle time from the PDH `PhysicalDisk` counters, a 10-minute realtime series, a per-minute downsample for the 24-hour history, and a log-spam detector (a process writing faster than X MB/s for Y minutes; a log file over 1 GB that is still being written). Read-only: nothing in the monitor can end or throttle a process.
- `nfd monitor [--seconds N] [--interval S] [--top N] [--json]` (JSON Lines, schema `nanofreedisk.monitor.v1`, `docs/schema/monitor-v1.schema.json`).
- **File-level disk activity with ETW** (`nfd_monitor::win::etw`): a private kernel trace session (`NANOFreeDisk Disk Monitor` — the shared "NT Kernel Logger" stays free for Process Monitor and WPR) reports reads and writes per process **and per file**, plus creates, renames and deletes under a watched folder. Needs an elevated process; a session left behind by a crash is stopped before the next one starts, Ctrl+C stops it, and a session that delivers no file events while the disks are busy falls back to the I/O counters. Files on drives without a letter, pipes and network files are left out. `nfd monitor --source auto|etw|counters`, `nfd monitor --watch <folder>` ("who touched this?"). A CI job runs the real session on GitHub's elevated Windows runner.
- **One elevated helper for sensors and the monitor** (`nfd-helper` protocol 2): Advanced sensors and the monitor's file-level detail share one helper process, so the second feature does not ask UAC again. The helper's requests stay a closed list (no command runs code, reads file contents or ends a process).
- **24-hour disk activity history** (`nfd-history` table `monitor_minutes`): per minute bytes read and written, peak rates and the busiest processes, recorded while the app's Monitor runs and history is on; cleared with the scan history. `nfd monitor --history [--json]`.
- **Disk activity view** (sidebar, Ctrl+K): live read / write chart (60 s or 10 min), every physical disk's throughput, queue, latency and busy time, processes sorted by reads, writes or IOPS, and — with file detail on (one UAC prompt, shared with Advanced sensors; nothing on the PC changes) — the files each process reads and writes and the files being written, with Show in Explorer and Analyze this folder. "End task…" opens the Tasks tab's guarded dialog. A 24-hour tab (per hour, top writers) and **Who touched this?** (pick a folder, see who creates, writes, renames and deletes files in it). Settings → Disk activity turns on the log-spam alert (X MB/s for Y minutes; log files over 1 GB being written).
- **Tray icon**: Open NANOFreeDisk, Pause disk monitor (in step with the view's Pause button) and Quit, in the UI language.
- Monitor overhead measured with a light write workload (`scripts/monitor-overhead.ps1`, `docs/monitor-overhead.md`): 0.03 % of all logical processors with the I/O counters on the reference laptop, 0.4 % with ETW on a 4-vCPU CI runner — the CI job fails if it ever reaches 2 %.
- **Installers** (Phase 8, `docs/PHASE8_INSTALLERS.md`): four packages per version, built by `scripts/build-packages.ps1`. **NANOFreeDisk Setup** (`apps/nanofreedisk-setup`, Rust + egui, needs no WebView2 itself): English/Vietnamese wizard in the brand colors, install for me (no admin, `%LOCALAPPDATA%\Programs\NANOFreeDisk`) or for everyone (UAC, Program Files), Start menu / desktop shortcuts and the Explorer menu as options, installs Microsoft's WebView2 bootstrapper when the runtime is missing (after checking it is signed by Microsoft), registers in Apps & features and uninstalls exactly the files it listed; silent `/S /D=<dir> /ALLUSERS /DESKTOP /SHELLMENU`, `uninstall.exe --uninstall /S [/REMOVEDATA]`. **MSI** (per machine, English and Vietnamese) and **NSIS** (per user) from the Tauri bundler, both shipping `nfd.exe`. **Portable zip**: with `portable.flag` next to the exe every piece of data — settings, history, logs, the system-drive quarantine and the WebView2 profile — stays in `data\` beside it.
- **Uninstalling never destroys files silently**: every uninstaller runs `nanofreedisk.exe --uninstall-cleanup` first. Items still in the quarantine are put back, deleted for good or left for a later install after a clear English/Vietnamese question; "remove my data" (NSIS checkbox or `/REMOVEDATA`, Setup checkbox) then deletes the data folders but keeps a quarantine that still holds files. The Explorer menu, shortcuts, Apps & features entries and installer registry keys are always removed; the shared PawnIO driver is never touched. A quiet MSI uninstall leaves user data alone.
- **Updates** in Settings: checks the latest GitHub release only when asked; NSIS and MSI copies download, verify (minisign key in `tauri.conf.json`) and install the new version, the portable and Setup copies get a link to the release page. `release.yml` writes `latest.json` when the signing key is configured.
- `release.yml`: manual runs default to a dry run (build + smoke test, no tag, no Release, no winget); SignPath code signing runs only once its secrets exist and is otherwise skipped with a notice; `scripts/smoke-test.ps1` installs, starts and uninstalls every package (MSI and "for everyone" when elevated) and fails on anything left behind — install folder, Apps & features entry, shortcuts, Explorer menu, registry keys and data folders.

- **Drive health, core** (`nfd-health`, Phase 7, `docs/PHASE7_HEALTH.md`): every physical drive with model, serial, firmware, bus, TRIM support and the drive's own warning / critical temperatures; the NVMe SMART / Health log (02h) and Identify Controller without administrator rights; the ATA attribute table through the storage driver; a Good / Caution / Bad verdict with CrystalDiskInfo's rules and the reasons behind it; volume checks (cluster size, 4K partition alignment, Windows TRIM setting, BitLocker state). Strictly read-only — the only drive commands that exist are SMART READ DATA / READ THRESHOLDS.
- `nfd health [--json] [--raw] [--disk N] [--redact]` (schema `nanofreedisk.health.v1`, `docs/schema/health-v1.schema.json`; exit code 1 = a drive needs attention, 2 = a drive is bad); validated on the reference PC's two NVMe drives (`docs/health-validation.md`).
- Administrator-only drive reads: SMART thresholds (`SMART_RCV_DRIVE_DATA`), SMART through USB bridges (SCSI / ATA Translation) and the volume dirty bit — directly in an elevated `nfd health`, or through the app's elevated helper with the new `Request::Health` (helper protocol 2: drive indices and drive letters only, never command bytes).
- **Health view** (sidebar, Ctrl+K, Home's "Is my drive healthy?"): a card per drive with its verdict, temperature against the drive's own limits, life left, power-on time and data written; the reasons in plain words; the NVMe health log or the S.M.A.R.T. table (key attributes in Simple mode, all with raw hex in Expert); notes for USB adapters and reads that need administrator rights; per-volume checks (free space and "full in ~N days", file system, cluster size, 4K alignment, TRIM, BitLocker, disk-check flag); *Read everything (administrator)* through the elevated helper; a self-contained HTML report and JSON export, without serial numbers unless asked.
- The **Health Score** counts drive health: a failing drive −45, a drive that needs attention −15, a drive at its own critical / warning temperature −10 / −4 (not twice when the Hardware Monitor already reported it), a volume marked for a disk check −10.
- **Drive alerts and tray icon** (G5): while the app runs it checks the drives 20 s after start and then every 30 minutes, and shows a Windows notification (and an in-app toast) once when a drive's verdict gets worse, a drive passes its own warning temperature (unless the Hardware Monitor's temperature alerts are on) or a drive drops below 10 % free; Settings → Drive health turns it off. A notification-area icon shows the drives' verdict and each fixed drive's free space, with Open and Quit.
- **One selection bar everywhere** (`SelectionBar.svelte` + `selection.ts`): Junk files, Dev caches (Cache, Repo, AI leftovers), Duplicates (files and folders), Old & large, Tidy up and Analyze share an always-visible bar — "N selected · M files · X will be freed" live, nothing selected = action disabled, items likely skipped (an app such as `claude.exe` still running) counted apart so the total is honest; Select all / Clear / Only "Safe" / Only "Caution" (Only "Advanced" in Expert mode; Protected and 🔒 Keep never selectable), a tri-state box per pack, vendor, project, repository, duplicate group (the copy that stays is never ticked) or list, Ctrl+A / Esc in the focused list. The main button shows the exact total ("Clean 3 items (14.9 GB)") and every confirmation repeats count and size per risk level; picking Caution / Advanced items needs an extra tick there. Selection never bypasses Planner → SafetyGate → Executor.
- **Clean one website's browser cache** (`nfd-browsers`, `docs/BROWSER_SITE_CACHE.md`): Junk files → Web browser caches → "Advanced: clean one website" (open in Expert mode, a disclosure in Simple) lists the websites in each Chrome / Edge / Brave / Vivaldi / Opera / Firefox profile's caches with their size, searchable, and removes only the ticked sites' entries — Code Cache (`js`, `wasm`), Service Worker CacheStorage (whole origin folder), Firefox `cache2`, and the HTTP cache where it uses the Simple format — as whole entry files plus the advisory index the browser rebuilds, through the quarantine (Restore in Activity, kind `browser-site`). Chromium's Windows HTTP cache (blockfile) is parsed read-only and its per-site share is shown but never edited. Cookies, logins, Local Storage, IndexedDB, History, passwords and extensions are never read; every path must also be covered by the browser's 🟢 Safe rule; nothing is planned while the browser runs and it is checked again while items move. CLI: `nfd browsers sites [--browser chrome] [--search] [--json]`, `nfd browsers clean-site <host> [--browser] [--exact] [--apply]` (schema `nanofreedisk.browsers.v1`).
- **Analyze suggests what to clean** (crate `nfd-advice`, `docs/ANALYZE_ADVICE.md`): every path of a scan gets a verdict — Safe to delete / Needs care / Guide only / Keep / Unknown — from everything the app already knows (rule packs and 🔒 Keep rules, build output by marker files, Claude Code worktrees checked with git and their sessions, conversation history, SafetyGate protected locations, Folder Encyclopedia guide articles such as WinSxS or pagefile, personal media, old installers and old large files, duplicates), with "if you delete this…", what is *not* touched and the right way to do it (the rule's own walk into the quarantine, build output into the quarantine, `git worktree remove`, the package manager's own command, the Recycle Bin, or only the guide). Folders add up by verdict ("80 GB can be freed safely, 2 GB must be kept"). After a scan Analyze opens on a **Suggestions** panel ("You can free X", safe / needs care / guide only / big but keep / junk elsewhere, one-click through the shared selection bar, 🟡 needs the tick and an acknowledgement, 🟠 Expert only, kept and live-session items never); the tree gets a verdict badge and a "Can free" column, the details panel a "Can I delete this?" card with the right action (no delete button for what must stay); treemap and sunburst become tabs, the treemap can color by verdict and draws fewer labels. Home's "Free X GB" and the Health Score (`reclaimable` replaces the Old & Large finding) use the same totals. CLI: `nfd advise <path> [--json] [--lang vi] [--no-git]` (schema `nanofreedisk.advice.v1`) and `nfd scan --advice`.
